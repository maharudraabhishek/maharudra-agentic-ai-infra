## How to write learning notes

Use learning notes when the work teaches an important concept, architecture pattern, MCP concept, AI infrastructure concept, security principle, debugging lesson, or workflow.

Do not only write copy-paste commands or prompts. Start with the concept, then show commands or prompts after the reader understands why they exist.

For every major implementation task, ask whether a learning note should be added or updated. Link to MCP, AI infra, architecture, security, or runbook docs when they provide deeper context.

When a concept involves a workflow, system boundary, service interaction, AI pipeline, or architecture decision, include a diagram when useful. Prefer beginner-friendly ASCII diagrams first. Use Mermaid diagrams when the flow is complex and the documentation renderer supports it. Every diagram should have a short explanation below it.

# Learning Note Template

## Concept

Explain the idea in simple words.

## Mental Model

Use a relatable analogy.

## Why It Matters

Explain the engineering value.

## Rudraloka Example

Show how it applies to this project.

## Flow / Architecture Diagram

Include an ASCII or Mermaid diagram when the concept involves a workflow, system boundary, service interaction, AI pipeline, or architecture decision.

## Tradeoffs

Explain pros, cons, and when not to use it.

## Common Mistakes

List mistakes to avoid.

## Related Docs

Link to architecture, MCP, AI infra, security, or runbook docs.
